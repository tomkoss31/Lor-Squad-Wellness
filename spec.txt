LOT 2 — `src/features/crm/filNote.ts` (NOUVEAU, pur, ~60 lignes)
═══════════════════════════════════════════════
Aucun import React. Testable en isolation.

```ts
export type RangEntree = "trace" | "main" | "parole";
export interface Entree { texte: string; rang: RangEntree }
export interface Fil { entrees: Entree[]; epingle: Entree; apercu: string; tronque: boolean }
export function filNote(notes: string | null | undefined): Fil | null
```

1) NORMALISATION — `const t = (notes ?? "").replace(/\r\n?/g, "\n").trim();` → si vide, `return null`.

2) DÉCOUPE — `t.split(/\s*\|\s*|\s*\n+\s*|\s+·\s+(?=🕑)/).map(s => s.trim()).filter(Boolean)`. Si 0 entrée → `null`. Les trois séparateurs sont ceux réellement écrits en base, chacun tracé à sa source :
   · `|`  → `make-lead-entrant/index.ts:302`, + la frappe de Thomas, + notre lot 1 ;
   · `\n` → `submit-prospect-lead/index.ts:202` (« ↩︎ Revenu·e le … ») ;
   · ` · ` UNIQUEMENT suivi de 🕑 → RPC `noter_disponibilites_lead` (migration `20261215200000`, l.63). Le lookahead est obligatoire : sans lui, un « · » de ponctuation couperait une phrase en deux.

3) `norm(s) = s.toLowerCase().normalize("NFD").replace(/\p{Diacritic}/gu, "")` — pour les tests seulement, JAMAIS pour l'affichage. La base mélange accentué (« Dispos indiquées ») et non accentué (« A ANNULE PAR MAIL »).

4) CLASSEMENT — ordonné, premier test gagnant. L'ordre est ce qui rend l'ensemble sûr : une trace ne peut jamais être promue en parole.
   a. `trace` — `norm(e)` contient l'un de : `"lead formulaire meta"`, `"arrive automatiquement via make"`, `"identifiant meta"`, `"numero normalise"`, `"prenom douteux"`, `"sms de premier contact"`, `"expediteur twilio"`, `"fusion du"`, `"fiche supprimee"`.
      ⚠️ CONTRAT À ÉCRIRE EN COMMENTAIRE DU FICHIER : toute nouvelle écriture automatique dans `notes` (edge function, RPC, script ops) ajoute son motif ici. Même statut que la règle « tout insert `client_messages` utilise un type de l'union `domain.ts` ».
   b. `parole` — l'entrée commence par `🕑` ou par `↩︎`, OU `norm(e)` matche
      `/\b(dispos? indiquees|dispo\w*|joignable|rappelle[- ]moi|(apres|avant|entre|des|jusqu.?a) \d{1,2} ?h|uniquement le|que le (matin|soir|samedi|week))\b/`
      ⚠️ AUCUN `\b\d{1,2} ?h\b` NU, jamais, même « pour élargir » : « son RDV du 03/09 14h » serait lu comme une disponibilité et ferait rappeler à 14 h quelqu'un qui a annulé. Toute reconnaissance d'horaire exige une préposition.
   c. `main` — tout le reste.

5) ÉPINGLE — la seule ligne visible au repos, choisie par NATURE et jamais par position :
   · la DERNIÈRE entrée `parole` s'il en existe (une dispo redonnée remplace la précédente) ;
   · sinon la DERNIÈRE entrée `main` ;
   · sinon la DERNIÈRE `trace` (on montre quelque chose plutôt qu'une carte vide — elle sera en encre atténuée, ce qui dit d'un coup d'œil que personne n'a rien dit).
   AUCUNE date n'est lue. `apercu` = `epingle.texte` avec `/\s+/g → " "`, coupé à 110 caractères à la dernière frontière de mot + « … » ; `tronque` dit si la coupe a eu lieu.

6) TEST `src/features/crm/__tests__/filNote.test.ts` — fixtures = les 7 échantillons réels, plus : la note de Justine, une note de 1038 caractères, une note 100 % traces, une note vide, `null`, une note d'une seule entrée courte, et « A ANNULE PAR MAIL son RDV du 03/09 14h » (doit être `main`, PAS `parole`).
